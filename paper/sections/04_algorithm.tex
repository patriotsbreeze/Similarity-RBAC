\section{The RBAC-HNSW Algorithm}
\label{sec:algorithm}

\subsection{Bitmask Encoding}
\label{sec:bitmask}

Each vector $v$ is assigned a 64-bit unsigned integer $v_m$ encoding its
access requirements.
A query with permission mask $q_m$ may access $v$ if and only if:
\[
  (v_m \;\mathbin{\&}\; q_m) = q_m
\]
This subsumes standard RBAC role-hierarchy checks.
The mask is stored adjacent to the node's vector pointer in memory, so a
single 64-byte cache-line fetch~\cite{drepper2007every} delivers both fields.
The bitwise AND and comparison constitute one CPU instruction
(${\approx}1$~ns), evaluated \emph{before} the distance computation
(${\approx}30$~ns for 768-dim cosine similarity).

\subsection{Two-Gate Greedy Search}
\label{sec:search}

Algorithm~\ref{alg:rbac_search} presents the modified HNSW layer-0 search.
The key change: when a neighbor $n$ fails the RBAC gate
(\textbf{Gate 1}, line~\ref{alg:gate1}), we do \emph{not} discard it.
Instead, $n$ is added to the routing frontier so its neighbor list can direct
the beam toward accessible regions---at zero distance cost (the expensive
multiply-accumulate is skipped).
Distance is computed (\textbf{Gate 2}, line~\ref{alg:gate2}) only when the
access check passes.
Figure~\ref{fig:traversal} illustrates why this prevents recall collapse:
the beam navigates through denied territory to reach the accessible cluster.

\begin{algorithm}[t]
\small
\caption{RBAC-HNSW Greedy Search (Layer 0)}
\label{alg:rbac_search}
\begin{algorithmic}[1]
\Require Graph $G$, query $\mathbf{q}$, query mask $q_m$, result count $k$, beam $\mathit{ef}$
\Ensure Top-$k$ accessible nearest neighbors
\State $\mathit{results} \leftarrow \emptyset$; $\mathit{routing} \leftarrow \{e\}$; $\mathit{visited} \leftarrow \{e\}$
\While{$\mathit{routing} \neq \emptyset$ \textbf{and} $|\mathit{results}| < \mathit{ef}$}
    \State $(d_c, c) \leftarrow \textsc{Pop}(\mathit{routing})$
    \ForAll{$n \in \textsc{Neighbors}(G, c)$, $n \notin \mathit{visited}$}
        \State $\mathit{visited} \leftarrow \mathit{visited} \cup \{n\}$
        \If{$(n.v_m \;\mathbin{\&}\; q_m) \neq q_m$} \label{alg:gate1} \Comment{Gate 1: RBAC}
            \State push $n$ into $\mathit{routing}$ (route; no distance) \label{alg:route}
        \Else
            \State $d \leftarrow \textsc{Dist}(\mathbf{q}, n)$ \label{alg:gate2} \Comment{Gate 2: distance}
            \State push $(d, n)$ into $\mathit{results}$ and $\mathit{routing}$
        \EndIf
    \EndFor
\EndWhile
\State \Return $\textsc{TopK}(\mathit{results}, k)$
\end{algorithmic}
\end{algorithm}

\subsection{Why Routing Through Denied Nodes Matters}
\label{sec:routing}

At 0.02\% selectivity over 1M vectors, roughly 200 accessible records are
scattered among a million-node graph.
Post-filtering with $\mathit{ef}\!=\!200$ explores 200 nodes: expected accessible
$=200\!\times\!0.0002\!=\!0.04$---far below the $k\!=\!10$ required.
RBAC-HNSW routes through denied nodes at \emph{zero distance cost} until
the beam reaches the accessible cluster.
This is related to ACORN~\cite{patel2024acorn} and VBASE~\cite{zhang2023vbase},
but requires no graph augmentation and targets bitmask RBAC specifically.
